# Серверный план расширения «Подхода»

Объём и критерии: [план iOS](https://github.com/nekell3r/podhod-ios/blob/main/docs/ROADMAP.ru.md). Пользователь включил питание, рецепты и КБЖУ. Android не дорабатывается; совместимость его запросов проверяется при изменении API.

| Направление | Серверная задача | Условие реализации |
|---|---|---|
| IOS-01: рабочая тренировка | Явные `removedSetIDs` в active/history: удаление незавершённого подхода с оценкой запаса, офлайн и защита выполненного | Реализовано; backend выпускается перед iOS, SQL-схема не меняется |
| IOS-02: замены | Исходная карточка сохраняется целиком; замена добавляется с пустыми подходами и новыми UUID | Существующий active/history контракт, без SQL-миграции |
| IOS-04: циклы/суперсеты | Тип дня, цикл, группы; измерения принадлежат телефону | Утверждение модели |
| IOS-05: прогресс | Первые отчёты из истории, агрегатный API по необходимости | Без универсальной аналитики заранее |
| IOS-06: рецепты | Лицензированный каталог, версии, источники значений и единицы | Проверенные данные до импорта |
| IOS-07: питание | Дни/цели, снимки КБЖУ, owner isolation, CAS, idempotency, удаление/экспорт | Контракт, миграции и тесты до UI |
| IOS-08: фото/замеры | Приватная модель, при синхронизации — закрытое объектное хранилище | Решение о хранении/восстановлении |
| IOS-09: Live Activity | Время принадлежит телефону, серверный push по необходимости | Сначала локальный iOS |

API и миграции описываются в API.md и проверяются с отдельной тестовой PostgreSQL. Источники схемы проходят deployment fingerprint gate, изолированную репетицию и отдельное одобрение. Автоматически менять разрешённый hash нельзя. Наличие экрана не означает готовность хранения и синхронизации.

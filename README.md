# Podhod backend

Общий сервер приложения «Подход»: программы тренировок, календарные недели, активная тренировка, история, протеин и каталог упражнений. Один Go-процесс обслуживает REST API и MCP; состояние хранится в PostgreSQL, входом управляет Keycloak.

Клиенты: [iOS](https://github.com/nekell3r/podhod-ios), [Android](https://github.com/nekell3r/podhod-android). Android-клиент пока не реализован.

## Проверка

Нужен Go 1.25 или новее.

```sh
go test -race ./...
go vet ./...
go build ./cmd/podhod
```

PostgreSQL-тесты включаются с отдельной тестовой БД через `TEST_DATABASE_URL`. Не указывай production-БД: тесты создают и очищают тестовое состояние. Остальные тесты работают без сервера и без секретов.

## Конфигурация и развёртывание

Пример переменных — `.env.example`; в нём только фиктивный домен. Секреты передаются файлом `DATABASE_URL_FILE` либо локальной переменной `DATABASE_URL`. В репозитории нет паролей, токенов, серверных адресов владельца или закрытых ключей.

См. [инструкцию развёртывания](docs/DEPLOYMENT.md). `deploy/prepare.py` генерирует новые случайные секреты локально, отказывается перезаписывать существующие и сохраняет их вне исходников. Прокси-конфигурация `deploy/nginx.conf` — пример для `api.example.com`, а не работающий публичный сервер.

## Контракты

- [REST API и форматы данных](docs/API.md).
- [MCP: инструменты, scopes и ошибки](internal/mcp/README.md).
- OAuth authorization code + PKCE S256 для нативного клиента; токены проверяются по issuer, audience, сроку действия, типу и subject.
- Состояние разделено по пользователю. Изменения защищены revision/CAS и request ID; история завершённых тренировок неизменна.
- Датированные недели и шаблон независимы от начатых и завершённых тренировок.

Существующая конфигурация `/v1/config` описывает клиент `podhod-ios` и callback `podhod://oauth/callback`. Для Android потребуется отдельная регистрация public OAuth-клиента и его redirect URI; секрет OAuth в мобильное приложение не помещается.

## Каталог упражнений

`internal/service/exercise-catalog.json` — основной источник каталога. Каталог отделён от снимков упражнений в программах и истории. Плановая нагрузка считается как прямые подходы + косвенные × 0,5; неразмеченные упражнения показываются отдельно.

Клиенты закрепляют экспорт каталога через `catalog.lock.json` с ревизией этого репозитория, версией каталога и SHA-256. В iOS есть `scripts/sync_catalog.py` для импорта из локального checkout бэкенда. Изменения каталога сначала коммитятся здесь, затем импортируются клиентами.
